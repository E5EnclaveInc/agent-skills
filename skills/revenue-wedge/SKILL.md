# Revenue Wedge

## Purpose
Prove the thing can take money — this week — with the smallest offer a real
buyer would pay for, on the thinnest stack that can accept payment. The wedge
funds the platform; never the reverse.

## Workflow
1. Inventory current assets: what's already built, who you can already reach,
   what trust you already hold. The wedge starts from here, not from zero.
2. Define the wedge: the smallest offer a real buyer would pay for this week —
   one job, one price, one buyer.
3. Name the first buyer by name (or exact ICP + contact path). "Small
   businesses" is not a buyer.
4. Pick the payment rail: the thinnest way to take money — a payment link, an
   invoice, a hosted checkout. No billing system, no subscription engine,
   until the second sale.
5. Separate built vs faked: what's real in the stack, what's manual behind the
   curtain — explicitly, in writing.
6. Map the path: waitlist → first paid → recurring, with daily metrics
   (signups, calls, sales, revenue) and a named owner for each number.
7. Define "first $1" precisely: who pays, for what, by when — then work
   backwards to today's task list.

## Output Contract
The wedge (offer, price, buyer, payment method, deadline), the built-vs-faked
stack list, and the waitlist→paid→recurring path with daily metrics and owners.

## Operating Rules
1. The first buyer is named, not segmented.
2. Payment on Day 1 means a link, not a billing system.
3. Manual behind the curtain is a strategy, not a shame — but it's written down.
4. Daily metrics have owners. A metric nobody owns doesn't exist.
5. No platform is built before the wedge sells. The wedge funds the platform.
6. Price from evidence (the demand-mining buyer card), never from aspiration.
